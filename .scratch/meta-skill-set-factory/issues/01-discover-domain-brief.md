# 01: Discover and approve a domain brief

**What to build:** A domain expert can explain the area and receive a concise, reviewable domain brief that captures the context needed to design useful skills.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Elicit intended users, recurring workflows, desired outcomes, constraints, terminology, and representative edge cases.
- [ ] Distinguish user-provided claims, sourced facts, assumptions, and unresolved questions.
- [ ] Identify preliminary domain risks and ask focused follow-up questions where critical information is missing.
- [ ] Avoid placing sensitive discovery context in packaged content unless it is explicitly reviewed and approved for inclusion.
- [ ] Include evaluation cases for relevant and nearby irrelevant discovery requests, plus observable brief-quality criteria.
- [ ] Keep the discovery capability independently usable without requiring the factory coordinator.
