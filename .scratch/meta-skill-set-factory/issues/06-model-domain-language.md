# 06: Model domain language and decisions

**What to build:** A domain team can maintain shared domain terminology and record significant domain decisions that keep related skills consistent.

**Blocked by:** 01: Discover and approve a domain brief; 02: Map workflows to bounded skill opportunities.

**Status:** ready-for-agent

- [ ] Identify ambiguous, overloaded, or conflicting terms and propose precise canonical definitions for user review.
- [ ] Maintain domain terms separately from implementation details.
- [ ] Stress-test important relationships and boundaries with concrete scenarios and edge cases.
- [ ] Record a decision only when it is hard to reverse, surprising without context, and the result of a real trade-off.
- [ ] Include evaluation cases for terminology clarification, scenario-based boundary checking, and irrelevant modeling requests.
- [ ] Keep the domain-modeling capability independently usable and avoid requiring persistent domain documents when none are needed.
