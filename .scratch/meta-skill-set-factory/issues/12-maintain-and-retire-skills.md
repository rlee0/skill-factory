# 12: Maintain and retire released skills

**What to build:** A skill-set owner can keep a released set trustworthy as domains, skills, and runtimes change, including safely updating or retiring capabilities.

**Blocked by:** 11: Prepare an evidence-backed set release.

**Status:** ready-for-agent

- [ ] Assess which skills, evaluation cases, safety reviews, sources, and runtime claims are affected by a proposed change.
- [ ] Recommend an independent set version change consistent with user-visible behavior and exact release membership.
- [ ] Re-evaluate affected skills against the runtime baseline and update evidence before making new support claims.
- [ ] Provide a clear path for deprecating or removing a skill and communicate the user-visible impact.
- [ ] Include evaluation cases for change-impact analysis, re-evaluation decisions, versioning, deprecation, and retirement.
- [ ] Keep the maintenance capability independently usable after the initial release workflow is complete.
